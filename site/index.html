03 / Package installation

Install only a real release.

Do not install a diagnostic preflight package expecting a game. Use the exact artifact and instructions published with a playable MuOS release.

Open the release page

Choose a release explicitly labelled for MuOS / H700. Read prerequisites, checksum and limitations.

Check the package type

A .muxapp is a MuOS application package. Never rename another archive to make it look installable.

Use Archive Manager

When the release provides a .muxapp, place it in the documented ARCHIVE location and install via Applications → Archive Manager.

Keep first boot conservative

Follow the release's data-path and launch instructions. Never copy desktop runtime files into MuOS.

At this revision the H700 preflight is diagnostic only and hardware gameplay acceptance is pending. If Releases contains no playable MuOS package, there is nothing to install as a game yet.
04 / User data

Your files stay yours.

Exact Twinsanity paths must ship with a validated MuOS package. Until then, do not guess a save or disc-image location.

Disc image

Bring your own supported image. The release must state the expected filename, directory and supported revision.

Memory cards

Back up saves before experimental updates. The final guide must identify the real save path and migration procedure.

Logs

Use the log path and collection method documented by the package. Include device, firmware and checksum in reports.

05 / Controls & performance

Mapped on-device.
Never guessed.

Physical controls, hotkeys, audio, frame pacing and renderer behaviour require a real H700 test report.

No button mapping or performance target is published as fact until checked on the actual device. The first accepted report will become the source for this section.
06 / Troubleshooting

Capture evidence first.

A useful report describes the exact handheld state.

Package not listed

Confirm extension, ARCHIVE destination and MuOS version. Do not rename the file.

App fails to start

Record error, device model, firmware and package checksum.

Black screen

Report whether MuOS returns, freezes or reboots. Include preflight logs if available.

Missing game data

Check the release's exact path and filename. Never post your disc image.

Input or audio issue

List the physical button and expected action, or describe the audio output route.

Send a report

Open an issue with reproduction steps, logs and device photographs where useful.

07 / Release desk

One target. Clear evidence.

Release notes must identify the tested H700 model and MuOS version, checksum, completed hardware gates and known limitations.
